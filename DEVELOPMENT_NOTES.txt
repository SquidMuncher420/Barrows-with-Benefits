BETTER BARROWS - IMPORTANT DEVELOPMENT NOTES

WHY READ THIS?

This file explains some mistakes and bugs found during development.

The goal is to stop a future developer from accidentally bringing an old bug back.


TUNNEL BUG: TRUSTING ONE CHAT MESSAGE TOO MUCH

An older version treated:

"You don't find anything."

as proof that a sarcophagus contained the tunnel.

Testing showed that this was not safe.

A brother could still appear.

The newer system waits for stronger evidence and also has a short fallback timer.

Lesson:

Do not turn the old single-message behaviour back on without understanding this bug.


TUNNEL KILL BUG: CHECKING THE PLAYER INSTEAD OF THE NPC

An older approach relied too heavily on where the player was standing when an NPC died.

This could make tunnel kill tracking inconsistent.

The newer approach checks the dying NPC's own location.

Lesson:

When deciding where a dead NPC belonged, information about the NPC itself is more directly useful than the player's position.


DOUBLE-COUNTING PROTECTION

The plugin remembers NPC objects it already counted.

This prevents one dead monster from accidentally increasing the counter twice.

Lesson:

Do not remove the counted-NPC protection just because it looks like extra bookkeeping.


NPC OUTLINE CHANGE

An earlier visual approach used a convex hull.

That creates a rough shape around the NPC.

The desired appearance was closer to RuneLite's normal model outline.

The plugin therefore moved to ModelOutlineRenderer.

Lesson:

The model-outline code is intentional and is not simply another way of drawing the same old polygon.


CHEST VALUE BUG TO AVOID

Suppose the player already owns 1,000 runes.

The chest adds 200.

The final stack is 1,200.

The chest reward was 200, not 1,200.

This is why the plugin compares the inventory before and after the loot.

Lesson:

Do not calculate chest loot by simply valuing the player's final inventory stacks.


WHY CHEST WAITING EXPIRES

The plugin only waits a short time for the expected chest inventory change.

Otherwise an unrelated inventory change later could be mistaken for chest loot.

Lesson:

Pending states should not remain active forever.


MINIMAP MARKERS ARE A SEPARATE DRAWING JOB

Drawing something in the main game world does not automatically put it on the minimap.

The minimap needs its own overlay and coordinate conversion.

Lesson:

If the mound is visible in the world but the letter is missing from the minimap, check BetterBarrowsMinimapOverlay rather than assuming the main mound overlay will handle it.


BUILD SUCCESSFUL IS NOT THE END OF TESTING

BUILD SUCCESSFUL means the Java project compiled.

It does not mean every RuneLite event happens in the order the code expects.

Always test event-based features inside RuneLite.


BEFORE A PUBLIC RELEASE

Test:

Every brother mound.

Every brother colour state.

Every minimap letter.

Tunnel discovery.

Tunnel memory.

Every tracked tunnel monster.

NPC target completion.

Door highlighting.

Puzzle help.

Reward potential.

Chest value.

Existing rune stacks.

Plugin enable/disable behaviour.

Then check the third-party notices and licence files.
